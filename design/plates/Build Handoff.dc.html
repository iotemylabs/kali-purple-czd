DRAFT UNTIL THE MATRIX IS GREEN
The release is a draft until plate 04 signs off. Publishing early is how an untested ISO gets onto a hundred laptops.
01 · ONE REPO, ONE SCRIPT
Splitting themes, live-build config and installer branding across three repos is how a volunteer project loses an image. Everything a build needs is in one clone, and the only entry point is build.sh — if a step is not in that script, it does not happen at release time.
02 · THE DESIGN SHIPS WITH THE CODE
Batches 01–09 live in design/ next to the packages they specify. An engineer changing the panel height can read why it is 56px without asking anyone, and a reviewer can tell intent from accident.
03 · THE GREP IS THE TEST
Token drift is the failure mode of every theme project: a hex gets pasted into a QML file, the gold changes, and one surface stays last year's colour. A hex anywhere outside tokens/ fails the release checklist, and it is one grep to prove.
04 · A TAG IS A PROMISE
The build string is not decoration — it is what a bug report quotes. It comes from the git tag, is written into the welcome app and the wallpapers at build time, and cannot be set by hand. Two ISOs with the same string are the same ISO.

// 02 · THE BUILD RUN
Six commands, in order
Run as root on a wired connection.
Do not build on the machine you are presenting from.
01
apt install live-build debootstrap squashfs-tools xorriso
Host prerequisites. Kali or Debian 13, amd64, nothing else tested.
2 min
02
git clone github.com/iotemylabs/czd-purple && cd czd-purple
Check out the tag you intend to ship, not main.
1 min
03
python3 tokens/generate.py
Token JSON → six toolkit files, four wallpapers, two boot plates.
20 sec
04
./build.sh --tag {{ tagLabel }}
Builds the eight .deb packages, then runs live-build. Logs to build.log.
45–70 min
05
sha256sum *.iso > *.iso.sha256 && gpg --detach-sign *.iso
IoTemy Labs' key, on an offline stick. Never in the repo.
3 min
06
gh release create {{ tagLabel }} --draft *.iso *.sha256 *.sig
Draft. It publishes only after the test matrix signs off.
10 min
WHEN IT FAILS
Nine times in ten it is a mirror timeout in debootstrap. Rerun step 04; the cache survives.
CLEAN REBUILD
./build.sh --clean before a release cut. Anything less is a stale chroot.
NO CI, ON PURPOSE
A 4 GB artifact and a signing key in a hosted runner buys nothing a laptop does not.
WHO CAN RUN IT
Anyone on the board with the repo and 40 GB free. The key holder is the only bottleneck.
01 · LITERAL COMMANDS, REAL TIMES
Every line is paste-able and every duration is measured on a 2021 laptop over wired ethernet, because "this takes a while" and "this takes 70 minutes" lead to different decisions about when you start. The long step is step 04 and it is unattended.
02 · THE GENERATOR IS STEP 03, NOT A HABIT
Because generated files are never committed, the build cannot use a stale wallpaper or last year's gold — generate.py runs before packaging every time, and its output lands in the working tree where a diff will show you what moved.
03 · THE KEY NEVER TOUCHES THE REPO
Signing is a separate step on an offline stick, which is also why there is no CI: a hosted runner would need the key to produce a signed image, and a security conference handing its release key to a cloud runner is a talk, not a practice.
04 · DRAFT IS THE DEFAULT STATE
Step 06 creates a draft release, so the download link cannot exist before the matrix is green. Making publication a deliberate, separate act is the whole safety mechanism — it is the one place this process is slower than it could be, deliberately.

IF YOU ONLY HAVE AN HOUR

01 · A LIST, NOT A PHILOSOPHY
Next year's builder is a volunteer with a deadline, so the respin is nine numbered edits with file paths — not an invitation to rethink the system. Two of the nine are genuinely hard (Kali rebase, Plasma drift); the other seven are text.
02 · THE NEVER-CHANGES COLUMN IS THE BRAND
Every item in it was a decision somebody argued for across batches 01–08. Writing them down as immovable is cheaper than re-litigating the gold every October, and it gives a new engineer permission to say no on the board's behalf.
03 · THE DATES ARE DATA
Because the event wallpaper and the welcome app read dates out of the token JSON, edit 01 does most of edit 02's work. Flip the respin year tweak to see the strings this plate would carry next October — that is the whole diff for a date change.
04 · AN HOUR IS A REAL SCENARIO
Conferences run late and volunteers get pulled. The fallback path names what to do with one hour and what to accept losing, so the failure mode is a thin respin rather than last year's ISO handed out with the wrong dates on the wallpaper.

WHO SIGNS OFF
IoTemy Labs, on the offline stick. One named person and a backup — not a committee.
01 · EIGHT CHECKS, ONE PER BATCH
Each row traces to a deliverable, so a failure points at a design decision and not a vibe. The passes when column is written so two different people testing on two different laptops reach the same verdict.
02 · BOTH PATHS GET TESTED
The image has to work as a live stick people boot at a workshop and as an installed system somebody runs all year. Testing only the live path is how the LUKS prompt and the installed panel ship broken — so row 02 is an actual install, on real hardware, every release.
03 · REMOVABILITY IS A RELEASE CHECK
The project's claim is that this is eight removable packages on stock Kali. If apt purge 'czd-*' leaves a broken desktop, the claim is false and the whole boundary from batch 07 collapses. Cheap to verify, so it is verified every time.
04 · PENDING IS GREY, NOT GOLD
An untested row wears PENDING in the same hue a signage board uses for nothing-live; a passing row goes gold-tinted. Flip the matrix state tweak for the signed-off frame — same table, one value changed, and the gate cell is the only thing that reads differently.
